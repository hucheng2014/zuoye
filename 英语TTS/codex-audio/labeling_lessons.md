# iLabel Lessons

## Core Rules

- `噪音` 按标注标准从严处理。任何非人声背景音乐、鼓点、女声哼唱、音效、电子声，都算杂音。
- `切音` 不是看句子像不像完整，而是看声音是不是没发完就仓促收掉。文本看起来完整，也可能仍然是切音。
- 文本必须按音频实际说出的字来写。音频里没说出来的字，不要补。
- 对 `切音` 的自动判断要保守。当前阶段只做高风险提示，不直接自动改页面。
- 对文本纠错，优先抓“页面多写了 1 到 2 个字、而两个转写模型都没听到”的情况。

## Operational Guidance

- 做新页时先抽查 3 到 4 条，先判断主音色，再开始整页标。
- `切音` 优先听最后 300ms 到 500ms，不要先看文本。
- 文本复核时优先检查句尾和专有词附近，那里最容易出现“脑补补字”。
- 酒类测评、开箱、桌面录音这类场景，要额外检查说话前 100ms 到 250ms，以及句中停顿位置有没有酒杯/桌面碰撞声。
- `噪音` 不能只靠整段 clean/noisy 分类。短促瞬态异响要单独复核。
- `噪音` 也不能只盯开头和停顿。后半句里和人声混在一起的器物声，同样要抓。
- 对 `噪音` 要同时防止误报。没有明确非人声证据时，不要因为整体发糙或模型分数偏高就直接标 `是`。
- 一旦怀疑 `切音`，文本要重点检查句尾是不是“残字模式”，常见表现是最后一个词只说出前 1 个字，例如 `代替 -> 代`、`资源 -> 资`、`圈子 -> 圈`。
- 文本不要为了通顺去删掉已经发出来的残字，也不要把残字脑补成完整词。
- 口头填充词 `呃`、`啊`、`嗯` 只要音频里说了，就要保留；它们本身不是杂音。
- 饮酒评测场景除了背景音乐、碰杯声，还要重点排查“酒杯落桌”“倒酒器皿碰撞”“杯口/酒具轻摩擦”这类很轻、很短、常和人声挨得很近的动作声。
- 看到文本里出现 `倒酒`、`喝一喝`、`闻这个`、`品鉴`、`酒具/珠子/瓶子` 这类动作语义时，要提高对器具杂音的敏感度。
- 特别短的句子，尤其是 3 到 10 个字的短句，噪音识别最不稳定。短句里要反过来优先怀疑“器物动作声是否被漏掉了”。
- 极短感叹句、短问句、动作句，不仅会漏杂音，也可能漏 `切音` 或 `韵律自然=否`，不能按“短句默认简单”处理。
- 自动化流程可以先跑 `噪音 + 双模型转写`，但 `切音` 暂时保留人工复核优先级，而且不要用尾部能量特征直接自动改。
