# 3D 点云分割试标题全自动化设计方案

## 1. 目标与验收标准

### 1.1 目标
实现 Appen 平台“3D 点云分割”试标题的**全程无人介入自动化**，即系统独立完成：
- 进入试标题页面
- 读取/解析点云数据
- 按规则完成地面/非地面/噪声分割
- 将结果写回页面
- 提交并通过试标题

### 1.2 验收标准（全部必须满足）
1. 试标题完成并提交成功
2. 试标题结果显示“通过”
3. 全程无需人工点击、确认或输入
4. 出现“长时间未操作”弹窗时，系统不依赖点击“继续工作”也能完成标注

## 2. 现状与关键约束

### 2.1 平台信息
- URL: `https://ui.appen.com.cn/ssr/tdl?...`
- 页面标题: 点云语义分割
- Template Type: `LIDAR_ANNOTATION_V2`
- 浏览器: Chrome 149，运行在 Ubuntu 192.168.50.97，CDP 端口 9239
- 当前连接: `http://192.168.50.97:9239`

### 2.2 业务规则（来自答疑文档）
| 类别 | 规则 |
|------|------|
| 地面点云 | 采集车能够行驶的路面 |
| 高度误差 | 与真实地面高度误差不超过 ±10cm |
| 路沿 | 路沿高度超过 10cm 不属于地面 |
| 斜坡 | 地下车库等斜坡按地面标注 |
| 上路沿 | 能行车 → 地面；只能行人 → 非地面 |
| 负地面 | 低于采集车行驶路面 → 非地面 |
| 草/植被 | 高于地面的草点 → 非地面（不标为噪声） |
| 试标范围 | 仅前 2 帧 |
| 提交流程 | 标注页“确认完成” + 试标首页再次提交 |

### 2.3 核心风险
- **长时间无操作弹窗**: 点击“继续工作”会刷新页面，导致已标注结果丢失
- **数据获取**: 点云数据可能通过内部 API 或 WebSocket 加载，需逆向获取
- **结果注入**: 需要找到页面内部标注状态更新机制

## 3. 总体方案

## 4. 模块设计

### 4.1 浏览器控制层 (Browser Controller)
- 连接 CDP: `http://192.168.50.97:9239`
- 定位标注页面 tab（`title=点云语义分割`）
- 持续心跳：每 30 秒触发一次 `mousemove` + `wheel` 事件，防止弹窗
- 弹窗检测：定期检查是否存在“监测到您长时间没有操作”弹窗
- 如果弹窗出现：
  - 不点击“继续工作”
  - 继续通过 CDP 执行 JS 完成标注
  - 必要时直接在后台新建页面重新加载任务

### 4.2 数据抓取层 (Data Fetcher)
多路径并行尝试获取点云数据：

**路径 A: API 直连**
- 已发现 API: `GET /api/v1/tdl?stepId=...&pageIndex=0&pageSize=1&tdlId=...`
- 当前问题：直接调用返回 `No value present` 错误页
- 需要获取正确的认证头或请求签名
- 监控页面正常加载时的请求头，复制完整的 `Cookie` + 可能的自定义头

**路径 B: WebSocket/内部状态**
- 监听页面 WebSocket 流量
- 扫描 `window` 对象查找包含 `points`、`frame`、`cloud` 的变量
- 扫描 Vue/React 组件内部状态

**路径 C: 3D 渲染层提取**
- 如果数据在 WebGL/Canvas 中，通过 Three.js 场景对象读取 geometry attributes
- 分析页面使用的 3D 库版本和暴露对象

**路径 D: 网络缓存/本地文件**
- 检查浏览器 Cache/IndexedDB 中是否缓存了点云文件
- 检查页面加载的 `.pcd`、`.bin`、`.las`、`.json` 文件 URL

### 4.3 点云分割算法 (Segmentation Engine)
基于规则的几何算法，不依赖深度学习：

1. **地面提取（RANSAC 平面拟合）**
   - 在 ROI 区域内（车辆前方可行驶区域）采样点
   - 使用 RANSAC 拟合地面平面
   - 保留平面附近 ±10cm 的点作为地面候选

2. **高度滤波**
   - 计算每个点相对于拟合地面的高度
   - 高度在 [-10cm, +10cm] 内 → 地面
   - 高度 > 10cm 或 < -10cm → 非地面

3. **噪声过滤**
   - 统计每个点的局部密度
   - 孤立点（密度极低）→ 噪声
   - 注意：草点等分散点按规则应归为非地面，不归为噪声

4. **路沿/上路沿处理**
   - 结合相机图像（C1 camera4）进行语义校验
   - 如果无法获取图像语义，保守策略：靠近道路边缘高处标为非地面

### 4.4 结果注入层 (Result Injector)
目标：将分割结果写回页面左侧实例树，使页面认为已完成标注。

**策略 1: 调用内部 API**
- 逆向页面 bundle 中创建实例、分配点的函数
- 通过 `page.evaluate()` 直接调用这些函数

**策略 2: 模拟用户交互**
- 选择左侧“地面点云”类别
- 在 3D 视图中使用页面提供的选取工具（如多边形、画笔）选中地面区域
- 重复“非地面点云”和“噪声点”

**策略 3: 直接修改 DOM/React/Vue 状态**
- 找到管理标注结果的 state 对象
- 直接写入分类后的点索引集合
- 触发 UI 更新

### 4.5 提交层 (Submitter)
1. 检查两帧是否都已标注
2. 点击底部“确认完成”
3. 等待返回试标首页
4. 点击“提交”
5. 捕获提交结果，判断是否通过

### 4.6 监控与日志
- 每步操作截图保存到 `/Users/xaa/zuoye/3d点云分割/logs/`
- 记录所有 API 请求响应
- 记录分割结果统计（每类点数）
- 记录提交结果和错误信息

## 5. 异常处理

### 5.1 弹窗出现
- 心跳未生效时弹窗出现：
  - 继续后台 JS 操作
  - 如果页面已冻结，新开 tab 重新加载任务 URL，从头自动执行

### 5.2 页面刷新/崩溃
- 实现断点重做：
  - 记录当前帧、当前状态
  - 刷新后自动重新进入试标题
  - 重新获取数据并重新标注

### 5.3 分割结果不通过
- 记录失败原因（如返回的错误信息）
- 调整参数（高度阈值、ROI 范围）后重试
- 最大重试次数 3 次

### 5.4 数据获取失败
- API 失败 → 尝试 WebSocket/JS 状态
- JS 状态失败 → 尝试 3D 渲染层提取
- 所有路径失败 → 记录错误并尝试截图视觉方案兜底

## 8. 第一阶段实施计划（MVP）

1. 搭建项目骨架和浏览器控制器

3. 实现点云数据抓取（优先 API + JS 状态）
4. 实现 RANSAC 地面分割 + 高度分类
5. 实现结果注入（优先内部 API，次选模拟交互）

## 9. 风险与备选

| 风险 | 影响 | 备选方案 |
|------|------|----------|
| 无法通过 API 获取点云数据 | 高 | 从 WebGL/JS 状态提取 |
| 无法找到结果注入 API | 高 | 模拟鼠标交互完成标注 |
| 分割精度不够导致不通过 | 高 | 调整参数多次重试 |
| 页面反自动化检测 | 中 | 降低操作速度、模拟人类事件 |
| 弹窗导致页面冻结 | 中 | 后台 JS 注入 + 重做机制 |

## 10. 决策记录

- **方案选择**: 方案 C（数据抓取 + 算法分割 + API/JS 注入）
- **不选方案 A 原因**: 纯前端 API 注入无法在没有原始点云数据的情况下计算分类
- **不选方案 B 原因**: 视觉大模型无法可靠完成 3D 点云语义分割
- **用户约束**: 全程无人介入，点击“继续工作”会导致刷新丢结果
