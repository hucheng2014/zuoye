Localization Issues Evaluation
The language in the response should be appropriate for the user prompt. 
•It should match the language of your locale and the language of the prompt. Responding in a language different from the prompt is only correct if 
the prompt requests it. 
•It should be free of language issues.
Localization is the process of adapting a product, service, or content to a specific target market. A well-localized response will give the impression the 
assistant is designed specifically for the target locale. T o achieve this, responses should:  
This task contains Prompt and Response written in a specific locale. Your role is to evaluate whether the response contains any localization issues 
described in this document. Note: The accuracy of the response is out of scope for this project (the response can be wrong but perfectly localized).

Localization Issues Evaluation
Scale Description Comments
No (no 
issues)
The response shows no signs of being generated for a different 
locale than the target one.
If there are any issues with localization, this should not be 
selected.
Yes 
(issues 
present)
There is at least one element of the response that would make the 
user question if the model were designed specifically for their 
locale.
If there are any issues with localization, this must be selected.
You will be asked to answer the question "Are there any localization issues in the response?" using the scale below.
1.Unlocalized Information 
2.Overly-localized Content 
3.Spelling  
4.Non-local Perspective  
5.Units of measurement (includes currency) 
6.Vocabulary  
7.Phrase or Idiom
Upon selecting “Yes” (the issue is present), you will mark all the localization issues you have found in the response: 
The last step is to provide the reasoning for your grading. Regardless of the locale, the comments should be written in English. Be specific and informative 
to provide additional context for your choice (e.g., why you have chosen a given issue and what part of the response points to that).  
8. Wrong Language  
9. Grammar  
10. Tone 
11. Awkward or unnatural writing 
12. Formatting and Punctuation  
13. Other

Localization Issues Overview                                                     
Issues Definition Examples
Unlocalized 
Information
The response provides information 
related to another locale when 
information more relevant to the target 
locale could have been provided 
instead.
Example 1: 
en_GB User Request: "What is the easiest way to file taxes?" 
Assistant Response: "Using IRS Free File. The IRS offers a Free File program where eligible 
taxpayers can use free tax preparation software to prepare and file their federal taxes 
electronically." 
Grade: Issues present, Unlocalized Information 
Explanation: The user is UK-based, but the IRS is a branch of the US government responsible for 
collecting taxes. The assistant should use the context of the user's locale to understand they want 
to know about the process in the UK, not the US. 
  
Example 2: 
en_CA User Request: When is the best time to visit Victoria?" 
Assistant Response: "Victoria, Australia, is a popular destination with diverse landscapes and a 
vibrant culture, making it a great place to visit throughout the year. However, the best time to visit 
Victoria depends on your personal preferences and the type of experience you want to have. Here 
is a breakdown of the different seasons in Victoria:" <list removed for brevity> 
Grade: Issues present, Unlocalized Information 
Explanation: Victoria, BC is the capital city of British Columbia, the 3rd largest province in Canada. 
The assistant should understand that based on the user's locale, this is the most relevant Victoria.

Localization Issues Overview
Issues Definition Examples
Overly-localized 
Content
The response unnecessarily fixates on the 
target locale. 
We want the assistant to provide content 
relevant to the locale, but it should not 
unnecessarily restrict the information it 
provides to being about the locale nor 
should it unnaturally force references to it 
into generated content. The assistant 
injects unnecessary locale specificity. 
Example: 
en_CA User Request: "What are the most influential books?" 
Assistant Response: "Canada has a rich literary tradition, and many Canadian 
authors have made significant contributions to literature. Here are some of the 
most influential books by Canadian authors: 
Classic Influential Books: 
1."Anne of Green Gables" by L.M. Montgomery (1908) 
2."The Handmaid's T ale" by Margaret Atwood (1985) 
3."Life of Pi" by Yann Martel (2001) 
4."The Stone Angel" by Margaret Laurence (1964) 
5."Fifth Business" by Robertson Davies (1970)" 
Grade: Issues present, Overly-localized content 
Explanation: This checkbox should be selected. The user did not request the list 
be only limited to Canadian authors, so the assistant should have considered 
books written by authors from all around the globe.

Issues Definition Examples
Spelling Any incorrect spelling, whether a typo, a 
non-standard spelling, a made up or 
gibberish word, must be marked as a 
localization issue.  
This applies to:  
Any foreign words within the response that 
are considered acceptable in the locale 
Any language or writing system (e.g, 
Chinese)
Example: 
en_GB User Request: "what is your favourite colour?" 
Assistant Response: "As an AI, I don't have personal preferences, including favorite 
colors. However, I can tell you that blue is often considered a favorite color worldwide." 
Grade: Issues present, Spelling 
Explanation: The assistant used en_US spelling for "favourite" and "colours". 
en_GB User Request: "Can you explain how photosynthesis works?" 
Assistant Response: "Photosynthesis is the process by which plants convert sunglight 
into energy." 
Grade: Issues present, Spelling 
Explanation: "sunglight" is not a valid English word. 
Refer to the Locale Variant Guide for more examples.

Localization Issues Overview
Issues Definition Examples
Non-local 
Perspective
The response is not from the 
perspective of the target locale. 
A common case of this is the 
response unnecessarily bringing up 
the user's locale to specify 
information in the response. 
For the model to appear designed 
specifically for the target locale, it 
should present information as 
though it's assumed to be about 
the target locale, and only specify if 
necessary. 
Example 1: 
en_AU User Request: "What is the most expensive housing market in the country?" 
Assistant Response: "According to the Real Estate Institute of Australia (REIA), Sydney, New South 
Wales, is currently the most expensive housing market in Australia. As of January 2023, the median 
house price in Sydney was AU$1.15 million." 
Grade: Issues present, Overly localized content 
Explanation: For an Australian user, the dollar value should be assumed to be in Australian dollars 
without having to specify 
Example 2: 
en_AU User Request: "How many Australian dollars are in an American dollar?" 
Assistant Response: " 
As of April 11th, 2023 
•1 AUD is approximately 0.66 USD 
•1 USD is approximately 1.50 AUD 
Currency exchange rates fluctuate daily, even hourly, so it's recommended to check with a currency 
exchange service or bank for the most up-to-date rate before making any international transactions." 
Grade: No issues 
Explanation: In this case, it's necessary to specify which dollar belongs to which country, so the 
specification is not a localization issue.

Wrong Language  The response contains foreign words 
that are not acceptable in the task 
locale (ranging from a single word to the 
full text). 
However: 
1.Responses that contain loanwords 
(borrowed or shared from other 
languages words) are acceptable if 
they are commonly used in the task 
locale. 
2.Responses that contain coding 
languages are acceptable if the 
request is asking for a coding solution. 
3.Responses that contain foreign 
languages are acceptable if the 
intention of the request requires the 
response to be in a foreign language 
or its acceptable in the locale (e.g., 
requests to translate from a task 
locale to a foreign language, user 
requesting restaurant name 
recommendations or brand names). 
It is unacceptable when a response is not in the same language as the request:  
User Request: iPhone15͸͍͘ΒͰ͔͢ (translation: how much is iPhone 15) 
Assistant Response: I'm sorry, your message is in a language that I cannot understand. This 
may be the result of an encoding error. 
User Request: 有关拜登减免学⽣债务的最新消息是什么？ 
Assistant Response: I am sorry, but I did not understand the request. Could you please 
rephrase your request in English? 
Acceptable: 
User Request: how do I say "hello" in Mandarin? 
Assistant Response: 你好 (translation: hello) 
Use Request: Translate "how are you" to Spanish 
Assistant Response: "¿Cómo está usted?” 
Loanwords are acceptable:  
1.Cul-de-sac (French): A dead-end street or road. 
2.Fiancé(e) (French): A person engaged to be married. 
3.Rendezvous (French): A meeting or appointment. 
4.Entrepreneur (French): A person who starts a business or venture. 
5.Angst (German): A feeling of deep anxiety or dread. 
6.Kindergarten (German): A preschool for children aged three to five years. 
7.Schnitzel (German): A breaded and fried meat cutlet, typically made with veal or pork.

         Important Note on Wrong Language and 
Satisfaction Ratings 
Responses that contain one or a few foreign words 
that are not acceptable in the target locale should 
still be marked as a Localization > Wrong 
Language issue. However, the Satisfaction rating 
should be determined based on the severity of the 
foreign-language content. Use your best 
judgement. 
•If the response is entirely or predominantly in the 
wrong language, it constitutes a critical failure 
and should receive a Highly Unsatisfying rating. 
•If the response is mostly in the correct language 
with limited language mixing, you should use 
your best judgment to select the appropriate 
Satisfaction rating. 
The evaluation tool now allows any Satisfaction 
rating to be selected after choosing Localization > 
Wrong Language, enabling more accurate 
reflection of issue severity.

Localization Issues Overview
Issues Definition Examples
Grammar The response contains grammatical errors that do not conform to 
native usage in the target locale.  
Note: In earlier versions of the guidelines, grammatical errors were 
considered localization issues only if they were correct in another 
locale variant. This restriction no longer applies. Any grammar that is 
incorrect for the target locale should now be flagged as a localization 
issue.
learnt (UK) vs. learned (US) 
Refer to the Locale Variant Guide for examples. 
Tone Any tone that is inappropriate, unnatural, exaggerated, stereotypical, 
rude, dismissive, unprofessional, or otherwise unsuitable for the target 
locale should be marked as a localization issue. 
Note: All tone-related issues should now be evaluated under the 
Localization dimension. Characteristics such as formal vs. informal, 
serious vs. humorous, optimistic vs. cynical, or sympathetic vs. 
sarcastic should be flagged when they negatively affect 
appropriateness, clarity, or user experience
Refer to the T one examples in the Grading Examples 
document. 
Awkward or 
unnatural writing
Wording or expressions in the response that lack the fluency expected 
of a native speaker. Here we focus on phrasing that is unnatural for a 
native speaker of the target locale even if it is grammatically correct. 
Note: If the wording is grammatically incorrect, the Grammar category 
should also be selected.
Refer to the Awkward or Unnatural Writing examples below.

Select this category when the response contains any formatting or 
punctuation errors in the text. This includes (but is not limited to) 
incorrect date or time formats, improper or inconsistent punctuation, 
inappropriate quotation mark usage, incorrect spacing conventions, 
or incorrect text direction (e.g., left-to-right vs. right-to-left). 
This category applies only to text-level formatting and punctuations. 
It does not apply to content organization choices, such as whether 
information is presented in paragraphs, lists, tables, or other 
structural layouts. 
Note: In earlier version of the guidelines, formatting and punctuation 
errors were flagged as localization issues only when they conflicted 
with the rules of target locale. Under the current guidelines, this 
distinction no longer applies. Any formatting or punctuation error in 
the response, whether locale-specific or universally incorrect, 
should now be flagged under this category. 
Refer to the Formatting and Punctuation examples in the 
Grading Examples document.
