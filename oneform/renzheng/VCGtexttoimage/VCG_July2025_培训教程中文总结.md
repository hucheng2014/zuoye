## 1. VCG 项目目标

VCG 是 Visual Content Generation，即视觉内容生成。项目核心不是生成图片，而是评估机器生成图片是否满足用户输入、是否质量足够、是否安全合规，并通过评价数据帮助模型改进。

评估人员的主要职责：

- 理解用户输入，包括文本、图片、草图、emoji 或组合输入。
- 判断输出图片是否安全，必要时应用 flag 或跳过。
- 按项目指南评估单张图片质量。
- 在多张输出之间做偏好排序。
- 写出清晰、具体、与评分一致的评论。

VCG 的风险包括误导性真实感图片、版权或商标风险、偏见与刻板印象、医学或现实场景中低质量增强图片带来的严重后果。因此图片质量、提示词匹配和安全筛查都必须认真处理。

## 2. 常见输出风格

不同子项目可能要求不同风格，常见类型包括：

- Animation：通常指现代 3D 动画风格，不是普通 2D 卡通人物。
- Illustration：偏插画、海报化、漫画感、色彩鲜明，常有较简洁背景。
- Sketch：细线条、较写实、像未完成的概念稿或素描，不能过于简单或不真实。
- Emoji：简洁数字图标，粗轮廓、亮色、夸张表情，用来表达情绪、概念或对象。

评估时要先确认项目要求的风格，不要把一种风格的标准套到另一种风格上。

## 3. 标准工作流

典型 VCG 任务按以下顺序处理：

1. 分析输入 prompt。
2. 根据项目要求应用安全或内容 flag。
3. 如项目要求，判断 human presence 或 anthropomorphism。
4. 对每张输出图片做单图评分。
5. 对多张输出图片做 side-by-side 偏好排序。
6. 提交清晰、具体、能解释评分理由的评论。

注意：不同项目可能增删某些维度，实际操作必须以对应项目指南为准。

## 4. Prompt 类型

常见输入类型：

- Text prompt：纯文本要求，可短可长，可明确也可含糊。
- Image prompt：用户提交图片，模型以图片为参考生成输出，不要求完全复制输入图。
- Image + text prompt：图片加文字，文字通常说明希望如何修改或使用图片。
- Drawing on image：用户在图片上画出想添加或修改的内容，模型根据标注生成。
- Sketch prompt：草图作为主要视觉输入。
- Emoji prompt：一个或多个 emoji 作为输入。
- Emoji + text prompt：emoji 提供主题或符号含义，文字补充动作、关系或细节。

准确识别 prompt 类型是正确评分的前提。

## 5. Prompt 分析方法

评估前必须先理解输入。推荐拆解为以下要素：

- 主体：人物、动物、物体、角色等。
- 动作：主体正在做什么。
- 属性与细节：颜色、材质、大小、表情、服装、数量等。
- 环境：地点、背景、时间、天气、周围元素。
- 风格或媒介：写实、emoji、素描、插画、特定艺术风格等。
- 情绪和氛围：平静、神秘、快乐、紧张等。
- 构图和空间关系：上下、左右、前后、视角、站位、是否在某物上。
- 隐含语境：例如 `cricketer` 不只是一名球员，也可能暗含球场、球衣、球、观众等。

非文本输入也要“阅读”：看图片、草图或 emoji 的主体、表情、动作、构图、风格和关键元素。

如果遇到不熟悉的文化引用、术语、风格或对象，可以做简短研究以正确理解 prompt。

## 6. 额外元素与冗余元素

输出图片可能包含 prompt 未明确提到的元素。不要自动扣分，先判断这些元素是否合理：

- 如果额外元素能支持场景、主题或氛围，通常可以接受。
- 如果额外元素与 prompt 有视觉或概念关联，通常不应扣分。
- 如果额外元素随机、分散注意力、抢占主体位置，或与 prompt 完全无关，应在 input-output alignment 中扣分。

例子：`dragon flying over a village` 中出现云、鸟或城堡，可以增强场景；但出现与龙和村庄无关的巨大物体并成为焦点，就可能影响对齐评分。

## 7. 模糊 Prompt 的处理

模糊 prompt 是指目标不清、细节不完整、存在多种合理解释，或只是一些松散关键词。

处理原则：

- 逐一识别每个概念，确保输出至少能体现所有核心概念。
- 抽象词需要合理符号化表达，例如 love 可由心形、花、亲密互动等表示；summer 可由阳光、海滩、夏日场景等表示。
- 判断概念应分开呈现还是可以整合。
- 只要整合在逻辑、风格或艺术上说得通，就可以接受。
- 不要求现实中一定合理，但图像内部要有可理解的连接。
- 创意可以接受，但不能丢失核心概念。

例子：

- `chef alien` 可以是厨师和外星人并排，也可以是穿厨师服的外星人。
- `whale farmer` 可以是鲸鱼穿农夫服、鲸鱼在耕作，或鲸鱼和农夫分别出现在海洋与农田中。
- `whale farmer scorpion` 这类多概念 prompt 中，不能把鲸鱼和蝎子做成无法辨认的怪异混合体，同时还缺失 farmer 概念。

## 8. Flag 与安全筛查

Flag 是决定是否继续评价的筛查步骤。常见类别包括：

- Inappropriate：不适宜内容，例如暴力等项目指南列出的类别。
- Sensitive：敏感内容，例如商标、版权、特定受保护内容等指南列出的类别。
- Stereotypes：刻板印象相关内容。

关键规则：

- 只有图片中清楚呈现相关内容时才打 flag。
- 不要仅因为文本 prompt 提到某内容就打图片 flag。
- 写实和风格化图片都可能需要 flag。
- 具体类别和处理方式以对应项目指南为准。

## 9. Human Presence 与 Anthropomorphism

此步骤只在项目指南要求时适用，主要判断输出图片中是否有人类存在或拟人化。

常见选项：

- 没有人类，也没有拟人化。
- 有人类，且人物较大、正面、面部特征可见。
- 有人类，但非正面或人物较小。
- 没有人类，但有拟人化。

Human presence 包括：

- 完整人类、局部人体、脸、手、腿、剪影等。
- 明确的人类剪影。
- 具有显著人类组成部分的神话生物，例如美人鱼、半人马。

Anthropomorphism 指给非人类实体赋予人类特征，例如：

- 动物或物体穿人类衣服、戴人类配饰。
- 动物或物体表现明显人类表情或情绪。
- 动物站立、说话、跳舞、开车、打牌、使用工具。
- 人类身体部件与物体或动物融合，例如心形长出人腿。

重要例外和易错点：

- 机器人、外星人、侏儒、僵尸通常不算 anthropomorphism。
- emoji 本身即使有表情或动作，也不算 human presence 或 anthropomorphism。
- 狮鹫、斯芬克斯这类非人类生物组合，不算 human presence。
- 人体部件单独出现可以算 human presence；但如果人体部件长在物体上，通常算 anthropomorphism。

## 10. 单图评分三大维度

多数 VCG 项目常见三个核心维度：

- Structural Integrity：结构完整性。
- Optical Fidelity：视觉/光学保真度、审美质量。
- Input-Output Alignment：输入输出对齐。

三个维度必须独立评分。不要因为某图对齐很好，就忽略结构错误；也不要因为图片很漂亮，就提高对齐分。

## 11. Structural Integrity 结构完整性

结构完整性评估图中主体和物体的解剖、结构、比例和视觉完整性是否合理。

重点看：

- 人类：眼、鼻、嘴、耳、手、手指、四肢、脸部比例等。
- 动物：腿、尾巴、头、爪、牙、耳朵、物种特征等。
- 物体：轮子、门窗、边缘、结构是否扭曲或融合。
- 文字：如果清晰可读，应检查是否乱码、拼写错误、变形。
- Artifact：不属于场景的多余残片、奇怪突起、错误附着物。
- Distortion：融化、扭曲、合并、比例严重异常等。

结构完整性是 prompt-relative 的：

- 如果 prompt 要求 `three-headed dog`，三头狗本身不算结构错误。
- 但三个头必须各自成形，不能互相融合或漂浮。
- 如果 prompt 要求 `baby with a beard`，不能因为婴儿有胡子不现实而扣结构分；要看胡子和婴儿本身是否画得正常。

推荐判断流程：

1. 先找主主体。最大、最清晰、最居中、最吸引注意的对象通常更重要。
2. 用 triage approach，从严重问题开始找，再看明显问题，最后看轻微问题。
3. 判断问题是否会立刻分散普通观看者注意。
4. 判断问题位置：主脸、手、主体中心的问题比背景角落问题更严重。
5. 综合问题重要性、大小、位置、对主体的影响给最终分。

常见等级：

- No issues：无明显结构问题。
- Minor：需要仔细看才发现的小异常。
- Noticeable：一眼或较容易发现，但未彻底破坏主体。
- Severe：明显破坏主主体基本形态或让图片非常不合理。

## 12. Optical Fidelity 视觉质量

Optical fidelity 衡量图片是否美观、清晰、有吸引力。常看三点：

- Clarity：清晰度、锐度、主体是否对焦，有无明显模糊、噪点、像素化。
- Color harmony：色彩是否协调，有无突兀或混乱。
- Lighting：光照是否自然、是否有深度、阴影是否合理。

常见等级：

- Highly appealing：构图好，主体清晰，色彩协调，光影有深度，整体审美强。
- Moderately appealing：整体可接受，但背景、细节、光照、对比度等有明显瑕疵。
- Not appealing：严重模糊、像素化、光照差、阴影混乱或整体观感差。

## 13. Input-Output Alignment 输入输出对齐

该维度衡量输出是否准确完整地反映输入。它与结构完整性和视觉质量独立。

通用流程：

1. 拆解输入中的所有关键元素。
2. 比对输出是否包含这些元素。
3. 检查对象、属性、动作、空间关系、情绪、氛围是否正确。
4. 判断缺失元素和冗余元素的重要性。
5. 根据指南评分。

如果只是缺一个次要元素，可能是部分降级；如果核心概念几乎缺失，即使保留了一个表面元素，也可能直接 fail。

例子：如果 prompt 是“一个男人站在街角商店后面，并带有特定背景/颜色关系”，输出只有一个男人站着，虽然包含“男人”和“站立”，但核心场景、关系、背景都缺失，可能应判为对齐失败，而不是简单部分对齐。

## 14. Text-to-Image 对齐

核心问题：图片是否准确、完整地表现文本 prompt？

评估时看：

- 主对象是否存在。
- 描述性细节是否正确。
- 空间关系是否符合要求。
- 情绪和氛围是否匹配。
- 是否缺失核心元素。
- 是否添加不合理的主要元素。

合理隐含元素不应扣分。例如巧克力条放在蓝色表面上，出现轻微倒影、包装纸或融化细节，如果不破坏 prompt，通常可以接受。

## 15. Image-to-Image 对齐更新

Image-to-image 中，输入图片不是精确蓝图，而是灵感和参考。但 2025 更新强调：主主体必须匹配。

重点规则：

- 输出应保留输入图的主主体、动作、环境类别、整体氛围和关键元素。
- 动物必须尽量保持同一动物，而不是相似动物。
- 猫狗等宠物还要关注品种、颜色等关键特征。
- 如果输入是黄貂鱼跃出水面，输出不应换成海豚。
- 如果输入是狐猴在树枝上，输出不应换成考拉。
- 如果狗的品种明显变了，即使其它元素基本一致，也应从高度对齐降到中等对齐。

Image + text 情况下，文字可以覆盖图片中的某些要求：

- 输入图是猫睡在床上，文字要求在海里，则输出应是同一只/相似猫在海中睡觉。
- 文字明确要求的变化不应因偏离原图环境而扣分。
- 输出仍应保留输入图的关键主体和文字指令共同要求的内容。

## 16. Sketch-to-Image 对齐更新

Sketch-to-image 的关键更新：评估对齐时忽略文本输入，只看草图。

规则：

- 输出应尽可能贴近草图中的对象、结构、布局和意图。
- 文本即使存在，也不作为 sketch-to-image 对齐的依据。
- 草图中的主形状、位置、视角、比例、背景/场景要尽量保留。
- 可以添加颜色、纹理、光照和真实细节，但不能违背草图意图。
- 即使草图是黑白，输出通常应有色彩。
- 输出不应变成拼贴图，除非草图本身就是拼贴。

## 17. Emoji-to-Image 对齐

Emoji 对齐会把输入拆成 emoji、文字说明或二者组合，逐项判断：

- Completely missing：概念完全缺失。
- Not well represented：概念存在，但外观或关键细节明显不对。
- Well represented：概念清楚、准确、可识别。

Emoji-to-image 的单侧评分常用不同尺度，例如 fairly / mostly / fully represented，而不是普通的 highly / somewhat / not aligned。

例子：狐狸 emoji + 墨镜 emoji + `wearing`，输出为狐狸戴墨镜，则狐狸、墨镜和 wearing 关系都被良好表达，可视为 fully represented。

会议补充：

- Emoji 相关主要规则没有重大变化。
- 任务 UI 中可能出现指南尚未充分说明的问题，例如肤色、性别、发色匹配等；按题目要求比较输入 emoji 与输出人物特征。
- Emoji + text 中，文本仍然重要，可以影响或覆盖 emoji 的解释。
- 大指南中 emoji alignment 相关页面需重点查看，会议中特别提醒关注 page 97。

## 18. 偏好排序

当任务提供多张输出图时，需要做 side-by-side ranking。

排序原则：

- 单图评分应指导排序。
- 如果一张图结构严重错误，通常不能排在只有明显错误的图前面。
- 排序可能按某个维度单独比较，例如只比较 structural integrity 或 input-output alignment。
- `Much better`：差异明确且显著，一张明显优于另一张。
- `Slightly better`：差异存在但中等，两张整体接近。
- `About the same`：没有有意义差异，或两张以相同方式好/坏。

注意：`About the same` 不代表两张都好，也可能代表两张都同样差。

## 19. 评论写法

评论的作用是向审核者和工程团队解释评分依据。高质量评论应：

- 使用图片编号或字母，如 A、B、C，不要只写 left/right。
- 与已选评分一致。
- 明确提到评估维度和具体问题。
- 说明哪些 prompt 元素缺失、错误或被很好体现。
- 简洁、结构清楚、避免空泛词。
- 避免语法和拼写严重影响理解。

不好的评论特点：

- 只写“quality good”“clear”“satisfied”等泛泛词。
- 和评分不一致。
- 冗长但没有具体问题。
- 在多个任务中复制同一套评论，只改少数关键词。

## 20. 认证与项目更新要点

2025-07-17 会议提到的更新：

- 旧 VCG 认证结果会重置，新认证结果用于未来生产资格。
- 新指南约 111 页，整合了更多子工作流和示例。
- 更新内容在指南中用紫色文字标出。
- 新指南包含 emoji-to-image、sketch-to-image、image-to-image 等更多信息。
- 认证前会有 mandatory knowledge check，通常是读取指南和正式认证之间的练习步骤。
- 会议当时要求优先完成 VCG 培训、knowledge check 和认证，再进入生产或其他任务。
- 如在重新认证前看到 VCG 生产任务，会议建议不要处理，应上报项目团队。

这些安排是会议当时的信息，实际状态以最新项目通知为准。

## 21. 实操检查清单

每个任务可按此顺序自查：

1. 先确认任务类型：text、image、sketch、emoji 或组合输入。
2. 拆解 prompt：主体、动作、细节、环境、风格、氛围、空间关系、隐含语境。
3. 判断是否需要 flag，且只基于图片中清楚呈现的内容打 flag。
4. 如有 human/anthropomorphism 问题，按输出图判断，不要把 emoji 本身算作 human 或 anthropomorphism。
5. 评 structural integrity 时先看主主体，再看严重程度、位置和 viewer impact。
6. 评 optical fidelity 时只看清晰度、色彩、光照和整体审美，不混入 prompt 对齐判断。
7. 评 input-output alignment 时逐项比对输入和输出，特别注意缺失的核心概念与不合理冗余元素。
8. Image-to-image 要保持主主体，动物和宠物品种/颜色要特别注意；文字指令可覆盖原图部分要求。
9. Sketch-to-image 只按草图评估对齐，忽略文本。
10. Emoji-to-image 逐个 emoji/文本元素判断 represented 程度。
11. 排序要和单图评分一致，按题目指定维度比较。
12. 评论要具体、简洁、能解释评分，不复制模板，。

## 22. 最容易犯错的点

- 把三个评分维度混在一起。
- 看到额外元素就自动扣 alignment 分。
- 忽略 prompt 中的空间关系、动作或氛围。
- 对模糊 prompt 过度要求现实逻辑，而不是看概念是否被合理表达。
- Image-to-image 中把动物换成相似动物还判高度对齐。
- Sketch-to-image 中错误参考文本输入。
- 把 emoji 表情当作 human presence 或 anthropomorphism。
- 没看清小 artifact、错误文字、手指/五官/尾巴等结构问题。
- 只因为图片漂亮就提高对齐分。
- 评论空泛、重复、和评分不匹配。
