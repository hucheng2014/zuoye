## 1. 文档目的

这份教程说明 VCG 项目中两个不同工作流的评估重点：

- `Base Creation`
- `Edit Model`

核心要求是：两个工作流必须按各自最新指南独立评估，不能混用过去的 Image Evaluation、ADM 或其他旧流程指南。评估员应先观看提供的录屏，再阅读并执行对应指南。评估时要慢下来、逐项核查，不要基于经验或直觉做未验证的假设。

## 2. 通用原则

### 2.1 先看录屏

在开始使用指南前，应先观看项目提供的录屏。录屏是指南的配套材料，有助于理解评分边界、示例和常见误判。

### 2.2 只使用当前工作流的新指南

`Base Creation` 和 `Edit Model` 各自有独立、具体的新指南。评估时必须以当前工作流指南为准，不应引用旧的图像评估指南、ADM 指南或以往项目经验作为判断依据。

### 2.3 不要匆忙或臆测

评估时要逐项确认图片内容、提示词要求和各评分维度。不能因为画面大致合理就跳过细节，也不能在看不清或信息不足时自行假设。

## 3. 两个工作流的关键差异

| 项目 | Base Creation | Edit Model |
| --- | --- | --- |
| Text Quality 与 Structural Integrity 的关系 | `Text Quality` 是独立维度，不放入 `Structural Integrity` 判断 | `Text Quality` 属于 `Structural Integrity` 的一部分 |
| 图片判断重点 | 生成图是否整体符合提示词、风格、质量和结构要求 | 编辑前后是否正确执行变更、未编辑区域是否保持、角色是否一致 |
| 人物属性评估 | 单人图不评估 apparent ethnicity 和 gender | 文档未特别说明单人属性规则，按 Edit Model 指南处理 |
| 左右图处理 | 文档未强调左右图逐张判断 | 必须先评估左图，再评估右图；每张图按每个维度独立判断 |
| 结构问题 | 重点检查人和动物的脸、眼睛、手指、肢体比例和数量 | 同样重点检查人和动物，并额外关注未编辑部分和角色一致性 |

## 4. Base Creation 工作流总结

### 4.1 模糊图片的判断

只有当整张图片都模糊时，才应将图片标为 blurry。如果只是背景模糊，而主体或主要内容清晰，不应仅因背景虚化就判定整图模糊。

这意味着评估时要区分：

- 摄影式景深或背景虚化
- 全图失焦、主体也看不清
- 局部区域模糊但不影响主体识别

### 4.2 Text Quality 是独立维度

在 `Base Creation` 中，文字质量单独作为 `Text Quality` 维度评估。不要把文字拼写、清晰度、可读性等问题并入 `Structural Integrity`。

实际判断时：

- 文字不可读或质量差，应在 `Text Quality` 中处理。
- 结构完整性只处理图像结构、形体、空间、解剖或对象构造等问题。
- 不要因为文字错误重复扣到 `Structural Integrity`。

### 4.3 图片中有文字但看不清时的处理

只要图片里出现了无法阅读的文字，就应标记为 `Low Quality`，无论提示词是否要求这些文字。

`can't tell` 只适用于一种情况：提示词要求出现文字，但生成结果中没有出现该文字，因此无法判断文字内容。这与“图片里有文字但读不清”不同。

判断边界：

- 有文字但不可读：`Low Quality`
- 提示词要求文字，但图里没有文字：`can't tell`
- 提示词未要求文字，但图里有不可读文字：仍按 `Low Quality`

### 4.4 Low Poly 风格必须有明确多边形特征

如果输出风格要求为 `Low poly`，画面主体必须明显体现多边形结构。常见特征包括三角形面片，也可能包括四边形面片。

不能只因为画面简化、卡通化或低细节就判定符合 `Low poly`。评估员需要放大并检查主体细节，确认是否真的存在多边形分面效果。

### 4.5 Photorealism 的判断

`Photorealism` 表示图像应该看起来像真实相机拍摄的照片。判断时应关注真实摄影感，而不是单纯“高质量”或“精细渲染”。

可核查的方向包括：

- 光照是否像真实环境中的摄影结果
- 材质、阴影、景深是否自然
- 人物、动物、物体是否没有明显 AI 生成感或插画感
- 画面是否更像照片而不是 3D 渲染、绘画、卡通或概念图

### 4.6 指南中的已知页码/示例错误

`Base Creation` 指南中存在两个已知问题，客户已被告知：

- 第 102 页标题写的是 Egyptian style，但示例图实际是 Persian paintings。
- 第 103 页标题写的是 Benin Bronze，但示例图同样是 Persian paintings。

评估时不要被这两个页码的标题误导，应意识到示例和标题不匹配。

### 4.7 apparent ethnicity 和 gender 的评估规则

当图片中只有一个人时，不评估 apparent ethnicity 和 gender。

当图片中是多人场景时，只要有一个人的脸看不见或无法判断，就应对 apparent ethnicity 和 gender 都选择 `can't determine`。即使其他人可以明显判断性别或族裔，只要组内存在一个无法看清的人，两个选项都应选择无法确定。

示例逻辑：

- 5 个人中 4 个人可判断，1 个人脸不可见：apparent ethnicity 与 gender 都选 `can't determine`
- 单人图：不评估这两个属性
- 多人图中所有人的脸都清楚：再按指南判断

### 4.8 放大图片进行细节检查

可以点击图片并使用 `+` 展开/放大。评估员应使用放大功能仔细检查图片，尤其是 `Structural Integrity`。

重点检查对象：

- 人类
- 动物
- 脸部特征
- 眼睛和视线方向
- 手指数量、形状和连接方式
- 肢体比例、数量和位置

明显的脸部扭曲属于严重问题。评估时要详细、按标准判断。大多数明显结构错误不应被轻描淡写地判为 `minor`。

### 4.9 Alignment 的完整覆盖要求

评估 `Alignment` 时，需要确认提示词中的所有元素都被正确覆盖，不能遗漏、部分出现或场景不符合要求。

例如提示词要求 “in a gym”，就必须确认场景确实像健身房，而不是只是室内空间或背景中有类似器材。评估重点不是图片整体是否好看，而是提示词要求是否被完整、准确执行。

## 5. Edit Model 工作流总结

### 5.1 Text Quality 属于 Structural Integrity

与 `Base Creation` 不同，在 `Edit Model` 中，文字质量属于 `Structural Integrity` 的一部分。

具体规则：

- 单词图片中出现拼写错误，可被视为 `Noticeable` 问题。
- 字母中有小瑕疵时，如果整体结构仍然良好、文字清晰可读，可以判为 `minor`。
- 判断重点是文字是否可理解、清晰，以及瑕疵是否破坏整体结构完整性。

这是两个工作流最容易混淆的地方：`Base Creation` 中文字质量独立评估，`Edit Model` 中文字质量并入结构完整性。

### 5.2 指南中的文字缺失修正

`Edit Model` 指南有几处已知文字缺失或页码内容问题：

- 第 37 页缺少一小段文字，缺失处应读作：`...reflecting in the output.`
- 第 64 页也缺少一部分文字，缺失处应读作：`...thus not a total failure.`
- 第 103 页和第 105 页内容重复，客户已知晓。
- 第 105 页本应列出当图片为 `Fair` 或 `Poor` 时可选择的 4 个原因，例如图片模糊、输出风格不同等。
- 第 121 页讲的是评论，不是 `Usability`；客户已知晓。
- 第 122 页才是与 `Usability` 相关的内容。

评估时应按这些修正理解指南，避免被页码、标题或缺失文字误导。

### 5.3 Visual Quality 与 Structural Integrity 可能重叠

部分看似属于 `Visual Quality` 的问题，也可能影响 `Structural Integrity`。文档特别提到不合理场景和空间布局这类情况。

实际评估时，如果画面布局、空间关系、物体位置或场景逻辑不可信，不能只把它当成视觉质量问题；它也可能构成结构完整性问题。

### 5.4 必须放大图片并逐项分析

`Edit Model` 也要求点击并放大图片进行评估。重点关注：

- `Structural Integrity`
- `Unedited portions`
- `Character consistency`

尤其要检查人和动物的脸、眼睛、视线、手指、肢体比例和数量。明显脸部扭曲应判为严重问题。明显错误通常不应被降格为 `minor`。

### 5.5 左右图必须分开评估

在 `Edit Model` 中，每张图片都必须按每个维度单独评估。流程是先评估左图，再评估右图。

不要把左右图混在一起做综合判断。例如左图在结构上有明显问题、右图没有问题，就不能给出一个合并后的平均判断；每张图都应有独立的维度评估。

### 5.6 必须核查提示词中的动作要求

`Edit Model` 的提示词通常包含明确动作，例如 change、remove、add 等。评估时必须确认模型是否执行了正确动作，以及所有要求元素是否被覆盖。

这些动作和元素会直接影响：

- `Instructions`
- `Alignment`

如果提示词要求删除某个元素但图中仍保留，或要求添加某个对象但未添加，应反映到相关维度中。

### 5.7 未编辑区域和角色一致性

`Edit Model` 与普通生成图不同，需要额外关注编辑是否只影响了该编辑的部分。

应检查：

- 未要求改变的区域是否被意外改动
- 原有角色是否保持一致
- 角色的身份、外观、位置或关键特征是否被不必要地改变
- 编辑是否破坏了画面原有结构或空间关系

## 6. 特定示例的评分修正

文档要求忽略某个关于儿童、救生圈和救生衣示例中的评分建议。

原建议中的 `Minor issues` 和 `Highly aligned` 是错误评级。正确理解是：

- `Alignment` 应降低，因为提示词对场景或元素的要求没有被充分满足。
- `Structural Integrity` 的问题应给更高惩罚，即判得更严重，而不是只记为轻微问题。

这个例子提醒评估员：不要机械接受示例中的建议评分。如果示例说明与实际评分标准冲突，应按当前修正后的说明处理。

## 7. 实用检查清单

### 7.1 开始评估前

- 是否已经观看录屏？
- 当前任务是 `Base Creation` 还是 `Edit Model`？
- 是否只使用当前工作流的新指南？
- 是否避免引用旧 Image Evaluation 或 ADM 标准？

### 7.2 检查图片质量和结构

- 整张图是否模糊，还是只有背景模糊？
- 人或动物的脸是否扭曲？
- 眼睛和视线是否合理？
- 手指数量、形状和连接是否正常？
- 肢体比例、数量和位置是否可信？
- 空间布局和场景关系是否合理？

### 7.3 检查文字质量

- 当前工作流是否为 `Base Creation`？如果是，文字质量单独评估。
- 当前工作流是否为 `Edit Model`？如果是，文字质量归入 `Structural Integrity`。
- 图片中是否有不可读文字？
- 提示词要求文字但图中没有文字时，是否正确使用 `can't tell`？

### 7.4 检查提示词对齐

- 提示词中的所有元素是否出现？
- 场景是否真的符合要求，而不是只近似？
- 要求的风格是否有明确证据？
- `Low poly` 是否真的有多边形分面？
- `Photorealism` 是否真的像相机拍摄？

### 7.5 Edit Model 额外检查

- 是否先评估左图，再评估右图？
- 每张图是否按每个维度独立判断？
- change、remove、add 等动作是否正确执行？
- 未编辑区域是否保持不变？
- 角色一致性是否保持？
- 编辑是否影响了 `Instructions` 和 `Alignment`？

## 8. 最容易犯的错误

- 把 `Base Creation` 的文字质量错误地扣到 `Structural Integrity`。
- 在 `Edit Model` 中没有把文字质量纳入 `Structural Integrity`。
- 只看缩略图，不放大检查脸、手、眼睛和肢体。
- 把明显结构错误判成 `minor`。
- 多人图中有一个人脸不可见时，仍然强行判断 apparent ethnicity 或 gender。
- 把背景模糊误判成整图模糊。
- 看到 `Low poly` 风格要求时，只看画面是否简化，而不检查多边形特征。
- 对左右图做合并评价，而不是逐图逐维度评价。
- 忽略 Edit Model 提示词中的具体动作要求。
- 被指南中已知页码错误、重复页或缺失文字误导。
