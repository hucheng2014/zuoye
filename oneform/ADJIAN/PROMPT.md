# AI Agent 自动化工作规范 — ADJIAN ASR 音频标注

> **在开始做题前，请仔细阅读并严格遵守以下规则。这些是不可违反的硬性要求。**

---

## 项目简介

本项目在 Docker 容器中进行 **ASR（语音识别）音频标注**任务：听音频、标注转录文本，需要严格的双模型 ASR 验证流程。

---

## 一、每条音频必须独立验证，禁止跳过验证

- **双 ASR 验证是硬性门槛**：每条音频必须通过 `local_segment_dual_asr.py` 成功验证后才能标注。
- 如果双 ASR 失败（HTTP 403、网络错误、空片段、脚本错误、缺少 tableData），**必须停下报告**，禁止从 `remark`、`user_remark`、可见文本或猜测来标注。
- **严禁**使用任务页面的 `自动标注` 功能。
- 静音/无效音频也需要跑双 ASR 验证确认后才能直接提交。

---

## 二、必须使用现有工具和环境

- 所有操作必须在 Docker 容器 `asr-worker-1-agent` 内执行：`docker exec asr-worker-1-agent`
- **禁止**使用宿主机的 Playwright/浏览器工具操作任务页面。
- 参考 `MEMORY.md` 中的已知问题和注意事项。
- SC 转录文本必须使用自然中文标点（包括句末标点，如 `好嘞，好嘞。`）。

---

## 三、严格按规范操作

- 新题到达时，**第一件事**是跑双 ASR 验证，其他页面操作都在验证之后。
- 仅包含极短峰值/片段、无法支撑完整话语的音频，视为无效/静音音频处理。
- 无效音频应选择 UI 提供的无效音频提交路径，而非编造转录文本。

---

## 四、遇到错误必须及时汇报

- 双 ASR 验证失败 → **立即报告**，不要尝试绕过。
- 同一错误重试 **≤2 次**，仍失败则停止并报告。
- 遇到登录/验证码/权限问题 → **立即通知用户**去 noVNC 手动处理。
- **严禁**静默失败或用备用方案（如 user_remark）绕过验证。

---

## 五、提交前必须复检

- [ ] 双 ASR 验证已成功完成
- [ ] 转录文本与 ASR 输出一致
- [ ] 中文标点正确、完整（含句末标点）
- [ ] 没有使用 `自动标注` 功能
- [ ] 没有从 remark/user_remark 复制内容

---
